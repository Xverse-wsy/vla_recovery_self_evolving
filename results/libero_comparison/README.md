# 四模型逐条评测结果与视频

本目录保存 Baseline、A60、B80、Stage1 的脱敏评测输出，包含 8,000 条逐条记录和对应的 8,000 段仿真视频。每个模型覆盖四个标准 LIBERO suite、每个 suite 10 个任务、每任务 50 个预设初始状态。

| 模型目录 | 成功数 / 评测数 | 成功率 | 视频数 |
| --- | ---: | ---: | ---: |
| `a60` | 1,519 / 2,000 | 75.95% | 2,000 |
| `baseline` | 1,484 / 2,000 | 74.20% | 2,000 |
| `stage1` | 1,268 / 2,000 | 63.40% | 2,000 |
| `b80` | 1,205 / 2,000 | 60.25% | 2,000 |

Baseline、A60、B80 为固定历史参考值，不安排复评；Stage1 使用本次完整评测成绩。A60/B80 的历史权重加载流程与 Stage1 不同，不能将该表解释为统一加载实现下的受控排名。详细实验定义和限制见 [结果与排查记录](../../RESULTS_AND_DIAGNOSIS.md)。

## 文件内容

每个模型目录包含以下四个文件：

| 文件 | 内容 |
| --- | --- |
| `summary.json` | 总成功数、成功率及四个 suite 的聚合统计 |
| `protocol.json` | 任务范围、推理参数、权重与归一化哈希、已记录的加载方式 |
| `episodes.jsonl` | 每行一条评测记录，含结果、步数、初始状态及动作哈希、对应视频位置与哈希 |
| `videos.zip` | 2,000 段原始 MP4 仿真视频，使用 Git LFS 保存 |

根目录的 `manifest.json` 记录各文件的字节数、SHA-256、模型成功数和核验范围。历史运行未保存加载策略字段时，`protocol.json` 明确标为 `not_recorded_in_historical_run`，不补造原始运行字段。

## 获取和查看视频

安装 Git LFS 后，在仓库中执行：

```bash
git lfs install
git lfs pull --include="results/libero_comparison/*/videos.zip"
```

解压相应模型的 `videos.zip` 后，视频按 `suite/task_XX/trial_YY.mp4` 排列；`episodes.jsonl` 中的 `video_file` 是 ZIP 内的相对文件名，`video_sha256` 可核对解压后的内容。若本地 ZIP 只是很小的文本文件，说明目前只有 LFS 指针，需要先下载 LFS 对象。

这些视频由评测程序直接写入仿真相机画面，没有重新编码或叠加本地终端信息。打包时逐个检查媒体 metadata、单视频流和帧数，检查 ZIP CRC，并保存每段视频的哈希；检查不等于逐段人工观看或完整解码所有帧。

## 脱敏与核验范围

结果从原始运行文件按明确字段列表提取，不包含个人目录、账户、凭据、内部服务、部署配置、设备或容量信息、实际运行耗时和自由文本日志。ZIP 内只保留任务与 trial 编号，归档时间使用固定值，不携带源文件时间和个人目录。

四模型逐条结果均完整且无重复，聚合成功数与原始汇总一致；相同任务和 trial 的初始状态哈希在四模型间完全一致。评测参数与归一化哈希一致，模型权重和加载实现的差异单独记录。初始状态在模型间一致，不代表它们与训练集不重合：本包不提供独立留出集保证，也不收录尚未统一核实的训练重合标记。

本包不包含模型权重、训练数据或环境安装包。成功率统计文件可直接读取；视频下载需要仓库对应的 LFS 对象可用。
